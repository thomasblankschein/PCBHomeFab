# Migration plan: from one package to REST services

Implements [ADR-001](architecture.md). Goal: the services `gateway`, `frontend`, `jobs`, `ingest`, `panel`,
`exposure` and `mill`, no shared code, REST only.

## Approach

- **Contracts first, then one service at a time.** Each step extracts one service from the existing code, proves
  it against the baseline outputs and switches the old pipeline over to call it.
- **The system keeps working after every step.** Until step 8 the existing `jobs` runner stays in place and calls
  the new services over HTTP one by one; the part not yet extracted still runs from the old library. A setting per
  service (`PCBHOMEFAB_<SERVICE>_URL`; empty = use the old library) allows going back.
- **Behaviour must not change.** Outputs are compared with golden files recorded in step 1.
- Each step is one or a few commits that leave tests and the smoke test green.
- No shared code also means: code is copied into the service and then stripped to what the service needs. The old
  library is deleted only in step 9.

## Order and reasons

`panel` first as a small pilot to prove the pattern (build, contract test, compose, switch), then `ingest` because
every other service depends on the canonical package, then `mill` (no image work, easy to compare), then `exposure`
(largest), then `jobs` last because it changes from "calls the library" to "calls the services" only once all of
them exist.

| # | Step | Result | Done when |
|---|---|---|---|
| 1 | Baseline | Golden outputs of the current code for the two real test boards: mask PNG, `.pm3`, every G-code program, layout. Stored small in `tests/golden/` or generated by a script and compared by hash. Tag `pre-services`. | a script reproduces the golden set and all current tests pass |
| 2 | Contracts | `contracts/`: OpenAPI per service, JSON schemas (board package `board.json`, layout, error codes), examples that are used as test fixtures, a README on how to change a contract. CI job that validates the files. | contracts reviewed and merged; examples validate against the schemas |
| 3 | Scaffold | `services/<name>/` skeletons (FastAPI app with `/healthz`, `X-Request-Id`, problem+json errors, per-request process with time limit and parallel limit), one `Dockerfile` each, per-service CI with path filter, contract tests (generated requests against the OpenAPI), compose with one internal network. Pattern is written once and copied into each service. | every skeleton builds, passes its contract tests and starts in compose |
| 4 | `panel` (pilot) | Packing code and its tests move into `services/panel`. `jobs` calls `POST /v1/layouts`. | golden layout identical; smoke test green; compose runs `panel` |
| 5 | `ingest` | Safe unzip, layer detection and canonical package builder move into `services/ingest`. `jobs` calls `POST /v1/packages`. Check early that the old loader can read the canonical package, so the not yet extracted parts keep working in between. If not, adapt that part of the old code in this step. | both real boards give valid packages; hostile ZIPs (path traversal, zip bomb, too many files) are rejected with the right problem code |
| 6 | `mill` | G-code, tool library and mill profiles move into `services/mill` with `GET /v1/tools` and `POST /v1/programs`. Reads Gerber / Excellon from the canonical package. `jobs` calls it. | every golden G-code program identical (byte comparison) |
| 7 | `exposure` | Rasterizer, mask, `.pm3` writer, printer profiles and the machine table fixture move into `services/exposure` with `GET /v1/profiles` and `POST /v1/masks`. `jobs` calls it. | golden PNG pixel-identical, `.pm3` identical or round trip pixel-exact, polarity test and Photon Workshop file test kept |
| 8 | `jobs` | `jobs` drops the library: workflow is only HTTP calls, SQLite and files stay here. Queue, expiry and limits keep their behaviour. The old settings per service URL are removed. | no import of `pcbhomefab` left in `services/jobs`; tests and smoke test green |
| 9 | Gateway and cleanup | Gateway routes `/` to `frontend` (placeholder page until milestone 5) and `/api` to `jobs`; internal services have no published ports. Delete `src/pcbhomefab/`, the CLI, the shared `tests/`; move remaining test data to the owning service. Update `README.md`, `CLAUDE.md`, `docs/deployment.md`, roadmap. | repository has no cross-service imports (checked in CI), only gateway ports published |
| 10 | Roll out | Deploy to the WSL test instance with the new compose file, run `scripts/smoke_test.sh`, compare with the golden set, check logs for request ids across services. | smoke test green on the test instance |

## Checks that enforce the principle (add in step 3, keep forever)

- CI step that fails if any file under `services/<a>/` imports or references the path of another service.
- Compose file has no volume mounted in more than one service and no published port except the gateway.
- Contract tests per service against `contracts/`; a changed contract fails the services that do not follow it.

## Risks

| Risk | Mitigation |
|---|---|
| Output changes during the move | golden files from step 1, compared after each step |
| Large payloads between services (`.pm3`, PNG, ZIPs) | measure in step 7; limits and streaming in the contract if needed |
| Synchronous call too slow for big panels | per-request time limit is a contract value; if it is hit, revisit asynchronous calls in a new ADR |
| Duplicated code drifts apart | accepted by ADR-001; the contract tests are what keeps services compatible |
| Debugging across processes | `X-Request-Id` is passed on and logged by every service from step 3 |
| Test instance and repository diverge | roll out each step to the test instance, not only at the end |

## Open points for later

- Authentication between services (internal network is enough for now; a shared token can be added to the contract).
- Whether `jobs` should be split into storage and workflow if it grows.
- Frontend build and its place in the repository (milestone 5).
